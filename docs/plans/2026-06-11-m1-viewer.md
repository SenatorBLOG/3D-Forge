# M1 — Viewer: model sources + selection UX

**Owner:** Mikhail · **Status:** in progress · **Branch:** `feat/m1-viewer`

## Goal

The viewer stops being hardwired to `robotic_hand.glb`. A user can load any GLB —
from a local file or a URL — and clicking the mesh produces a *region*, not just a
point: the selected sub-mesh is highlighted and its name is reported alongside the
3D coordinates. This is the data the Spatial Prompt Engine (M3) will consume.

## Acceptance criteria

1. `npm --prefix client run build` passes.
2. Default model (`robotic_hand.glb`) still loads and is selectable as before.
3. "Upload .glb" lets the user pick a local `.glb`; the viewer swaps to it. (manual)
4. Entering a model URL and pressing Load swaps the viewer to that model. (manual)
5. A failed load (bad URL, corrupt file) shows an error message in the UI instead of
   a blank viewer or console-only error. (manual)
6. Clicking the model highlights the hit sub-mesh and the sidebar shows its name
   (region label) plus the click coordinates. (manual)
7. Switching models clears the previous selection and releases the previous model's
   resources (no leaked object URLs; geometries/materials disposed).

## Tasks

1. **ModelViewer: selection result + highlight** — `client/src/components/ModelViewer.jsx`
   - `onSelect({ point, meshName })` instead of `onSelectPoint(point)`; mesh name
     resolved by walking up parents until a named node is found.
   - Highlight the hit mesh by swapping in a cloned material with an emissive tint;
     restore + dispose the clone on re-selection, model swap, and unmount.
   - `onLoaded` / `onError` callbacks for load lifecycle.
2. **App: model source controls** — `client/src/App.jsx`
   - State for model URL, load status, error, selection.
   - File input (`.glb`, via `URL.createObjectURL`), URL input + Load, reset to
     default model. Revoke stale object URLs on swap.
   - Sidebar shows region label + coordinates; loading/error overlay over the viewer.
3. **Styles** — `client/src/index.css` for the model-source section and overlay.

## Out of scope (follow-ups within M1)

- Multiple simultaneous markers / multi-region selection.
- Uploading the model to the server (client-side only for now).
- Region label heuristics beyond mesh names (e.g. geometric part naming).

## Risks

- Cross-origin model URLs depend on the remote server's CORS headers — surfaced as
  a load error with a hint, not solvable client-side.
- GLBs with multi-material meshes: highlight is skipped (selection still works).
